# Journal Schema

Daily files live at `journal/YYYY/MM/YYYY-MM-DD.md` — one file per day, append-only.

## Template

```markdown
# Journal: YYYY-MM-DD

## Learnings

### HH:MM | [learning] Title
- **Context**: What project/task triggered this
- **Insight**: The actual learning
- **Evidence**: File path, error message, or code snippet
- **Tags**: #tag1 #tag2

## Decisions

### HH:MM | Decision Title
- **Options**: A, B, C
- **Chose**: B
- **Rationale**: Why
- **Revisit if**: Conditions that invalidate this decision

## Patterns

### HH:MM | Pattern Name
- **Where**: Codebase/context
- **Pattern**: Description
- **Apply when**: Trigger conditions
- **Avoid when**: Counter-indications

## Mistakes

### HH:MM | What went wrong
- **Expected**: ...
- **Actual**: ...
- **Root cause**: ...
- **Prevention**: ...

## Auto-Extracted
<!-- Entries below this line were auto-generated by session-learnings-extractor -->
```

## Design Decisions

- Markdown — git-friendly, human-readable, Claude-native
- One file per day — prevents directory explosion, enough granularity
- Append-only — no contention, simple git merge
- `## Auto-Extracted` section separated from manual entries — user can distinguish and prune
- Tags as inline `#hashtags` — greppable without a taxonomy database
